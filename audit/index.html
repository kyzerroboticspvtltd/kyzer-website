The rate limiter used a module-level Map — counters reset on every cold start.
✓ Fixed — Replaced with Upstash Redis (@upstash/ratelimit). Persistent across all serverless instances. Deployed 21 Jun 2026.
CRITICAL — FIXED

No rate limit on /api/my-orders

Firebase token auth is in place but no rate limiting. An attacker with valid tokens can hammer this endpoint with no throttling.
✓ Fixed — 20 req/min per IP via rateLimit(). Deployed 21 Jun 2026.
🟠 High — Open
HIGH

Sheet sync token compared with == (timing attack)

Plain string equality leaks timing info, enabling offline brute-force of the token.
src/app/api/sheet-sync/route.ts — Line 25: return token === SYNC_SECRET
Fix: crypto.timingSafeEqual(Buffer.from(token), Buffer.from(SYNC_SECRET))
HIGH

Service key falls back to anon key in track-visit / analytics / publish

If SUPABASE_SERVICE_KEY is missing, these routes silently fall back to the anon key.
src/app/api/track-visit/route.ts · analytics/route.ts · publish/route.ts
Fix: Throw 500 if SUPABASE_SERVICE_KEY missing instead of falling back.
HIGH

Firebase token expiry not explicitly validated

verifyFirebaseToken() calls Firebase's accounts:lookup but doesn't decode/check the exp claim. Stale tokens may be accepted.
src/app/api/my-orders/route.ts — Lines 11-29
Fix: Use firebase-admin SDK — validates expiry, signature, revocation in one call.
🟡 Medium — Open
MEDIUM

No email validation on support ticket submission

body.email used without calling isValidEmail() — invalid addresses stored in DB and sent to admin.
src/app/api/support-ticket/route.ts — Line 23
Fix: Add if (!isValidEmail(email)) return 400 — isValidEmail exists in src/lib/sanitize.ts.
